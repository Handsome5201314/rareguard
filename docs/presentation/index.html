01 / 为什么做

夜里最难的不是看见数据

家长需要的是：什么时候该起身，起身之后该看什么。

一夜的记录如果散在戒指、手机、服务端和对话里，家长仍然只能靠猜。

RareGuard 把“昨晚发生了什么”变成一条可以回看的记录：有时间、有来源、有质量，也保留缺口。

目标不是替家长下结论，
而是让下一步行动有依据。

辅助监护 · 描述性记录 · 不做发作诊断

02 / 产品全景

一条夜间记录，四层产品共同完成。

每一层负责一个清楚的问题。数据先有归属，解释才有边界。

戒指

贴身采集设备可提供的生理信号与设备状态。

RareGuard APP

本地连接、队列和上传状态，记录数据缺口。

病程云端服务

患者、授权、采集记录、事件和夜间工作台的承载层。

Octop 项目智能体

只读取获授权记录，生成时间轴与验收复盘。

四层连成一条可信记录

03 / 家庭端

手机端先把“今夜状态”说清楚。

家长看到的是状态、缺口和下一步。

RareGuard APP 是家庭端入口。它连接戒指，保留离线队列，并把上传状态交给病程云端服务管理。

04 / 云端服务

病程云端服务，是整条记录的承载层。

把授权和数据放在同一个可核对的工作台。

07 / 智能体如何工作

Octop 负责把记录整理成可以复盘的回答。

每一步都能回到数据来源，权限不会随着对话扩大。

01 / 授权

只读连接

用户在病程本生成 Octop 只读连接包，授权对象和有效期清楚可见。

02 / 查询

读取时间窗

按患者、时区和时间窗查询已授权的夜间记录。

03 / 整理

生成时间轴

把心率、血氧、体动、缺口、设备事件和家长观察分栏呈现。

04 / 回答

解释边界

描述相对个人参考范围的变化，说明来源和质量，不输出发作诊断。

关键边界： Octop 只读记录，不自动给药，不修改提醒阈值，不把“建议查看”写成“发生了发作”。

08 / 一次提醒的来路

每一次提醒，都能回到它的证据链。

家长收到的是“请查看”，不是一个黑箱结论。

戒指提供信号，手机记录接收与上传，病程服务保留上下文，Octop 帮助把证据整理成可读的时间轴。

辅助监护 · 不构成医疗诊断

设备测量

记录信号、设备时间和质量。一次测量不等于连续监测。

手机接收

记录收到时间、上传队列和连接缺口，不把手机收到时间当成设备测量时间。

云端承载

病程服务按患者、时间窗、来源和事件保存记录。

智能体复盘

Octop 解释“相对平时哪里变了”，把下一步留给照护者和既有方案。

缺数据必须显示为缺数据，不能被解释成“没有事件”。
